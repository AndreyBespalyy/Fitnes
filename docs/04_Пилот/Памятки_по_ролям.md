# Памятки по ролям для обучения (шаг 17)

**Формат:** 1 час на роль. Каждый сотрудник проходит свой сценарий сам на тестовых данных, а ведущий смотрит, где он застрял.

**Где лежат подробности:** в папке docs/03_Инструкции.

**Вход:**
- сайт https://app.amoglobal.ru, на телефоне — приложение (см. [Мобильное_приложение.md](../03_Инструкции/Мобильное_приложение.md));
- при первом входе система попросит сменить временный пароль.

## Менеджер отдела продаж

**Утро:**
1. «Звонить» → «План дня»: сколько нужно продать сегодня и кому звонить первым.
2. «Задачи»: сначала просроченные, потом на сегодня.

**Новый лид:**
- придёт уведомление на телефон;
- ответить нужно в норму клуба (по умолчанию 5 минут);
- кнопка «📞 Позвонить», затем «Выполнить»: коротко записать результат и поставить следующий шаг.

**Правило:** у открытой сделки всегда есть следующая задача. Система не даст закрыть задачу без неё.

**После звонка:**
- в «Звонках» проверить черновик итога от ИИ и подтвердить (если включён ИИ-сервер);
- без ИИ-сервера итог пишется вручную.

**Встреча:** назначить из сделки, после встречи отметить «пришёл» или «не пришёл».

**Продажа:**
- «Клиенты» → карточка → «+ Продать» → «Оплата»;
- договор печатается или подписывается на планшете.

**Отказ:** перевести сделку в «Отказ» и обязательно указать причину.

**Сценарий проверки:** принять лид → позвонить → назначить встречу → провести → продать абонемент с оплатой частями.

## Руководитель отдела продаж

- **«Рабочий стол»:** план и факт отдела, светофор по менеджерам, конверсия по каналам.
- **«Задачи» → «Все в клубе»:** у кого просрочки.
- **«Звонить» → «Горячий список» → «Весь клуб»:** кто из клиентов не в работе. Отсюда раздаются клиенты.
- **«Звонки» → «Качество ИИ»:** оценить итоги («ок / мелкие правки / существенные»).
- **«Теневой режим»:** первые две недели сравнивать, покупают ли «горячие» чаще.
- **Задачи «Проверить: продажа без оплаты»:** выяснить у менеджера, что случилось.

**Сценарий проверки:** найти просроченную задачу менеджера → переназначить сделку → оценить итог звонка.

## Ресепшн

- **Смена:** «Финансы» → «Открыть смену». Без открытой смены наличные не принимаются. Вечером «Закрыть смену», система сверит кассу.
- **Проходы:** клиент прикладывает карту или браслет. При отказе система пишет причину. «Ручной проход» — только с указанием причины.
- **Новый клиент у стойки:** «Лиды» → создать.
- **Продажа и оплата:** карточка клиента → «+ Продать» → «Оплата»; чек уходит в кассу.
- **Возврат:** в абонементе «Возврат денег»; сверх лимита ресепшн утверждает управляющий.

**Сценарий проверки:** открыть смену → пропустить клиента → продать гостевой визит за наличные → закрыть смену.

## Управляющий клубом

- **Всё, что собственник, но в своём клубе:** прейскурант, заморозка, рассрочка, нормы KPI, план продаж («Рабочий стол → План продаж», есть «Расчёт ИИ»).
- **Утверждает:** возвраты до 15 000 ₽, скидки до 15 %, расходы до 50 000 ₽. Больше этих сумм утверждает собственник.
- **«Сотрудники»:**
  - добавить сотрудника и выдать временный пароль;
  - «Заблокировать» — при увольнении;
  - «Устройства» → «Завершить все сеансы» — если сотрудник потерял телефон.
- **«Сообщения»:** какие автосообщения включены.

**Сценарий проверки:** поменять цену тарифа → утвердить возврат → задать план месяца → заблокировать тестового сотрудника.

## Финансист

- **«Финансы»:** журнал платежей, долги, ДДС, план-факт.
- **Сверка с банком:** загрузить выписку → разобрать операции без пары (по ним придёт задача).
- **Расходы:** завести расход, его утверждает управляющий или собственник по лимиту.
- **Касса:** «Касса» → чеки с ошибкой → «Повторить».

**Сценарий проверки:** загрузить выписку → сопоставить операцию вручную → провести расход.

## Собственник

- **«Рабочий стол»:** сравнение клубов, план и факт сети, риски.
- **Утверждения сверх лимитов управляющего:** возвраты, расходы.
- **Отчёты и выгрузки:** «Отчёт по продажам» → XLSX.
- **Настройки любого клуба.**

## Администратор системы

- **Клубы:** при создании выбирается модель продаж.
- **Воронки:** этапы сделок.
- **Источники заявок:** ключ для сайта, проверочная заявка (`"test": true`) — проверяет подключение, ничего не создавая.
- **Перенос из 1С:** загрузка, сверка, принятие.
- **Сотрудники всех клубов.**
