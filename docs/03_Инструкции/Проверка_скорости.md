# Проверка скорости на объёме настоящей сети

Пункт 14 списка «20 улучшений». На тестовых данных (десятки клиентов) всё открывалось мгновенно. Чтобы не узнать о тормозах в день переноса из 1С, сделали отдельную базу размером с настоящую сеть и замерили 39 главных экранов и отчётов.

## Объём проверки

30 тысяч клиентов, 49 тысяч абонементов и договоров, 235 тысяч начислений и оплат за 3 года, 1 миллион посещений, 12 тысяч заявок и сделок, 200 тысяч записей журнала. Замеры сделаны под обычными ролями (собственник, управляющий, менеджер, ресепшн, финансист) с защитой данных по клубам.

## Что было медленно и что стало

| Экран | Было | Стало |
|---|---|---|
| Загрузка клуба по часам | 19 с | 0,7 с |
| Утренняя сводка | 7,4 с | 0,02 с |
| Удержание: когорты | 4,1 с | 0,9 с |
| Проходы: отчёт за неделю | 2,6 с | 0,1 с |
| Удержание: сегменты | 1,6 с | 0,5 с |
| Ресепшн: поиск клиента | 1,2 с | 0,01 с |
| Поиск клиента по телефону | 1,0 с | 0,03 с |
| Проходы: лента | 0,95 с | 0,01 с |
| Кому звонить | 0,95 с | 0,2 с |
| Список и поиск клиентов по фамилии | 0,5 с | 0,05–0,1 с |

Сейчас все рабочие экраны открываются быстрее 0,5 секунды, тяжёлые отчёты за длинный период (прибыль, когорты, загрузка) — быстрее 1 секунды.

## Что сделано

- Добавлены индексы для частых запросов: телефон клиента, поиск по части телефона и фамилии, начисления, оплаты, продления, сделки, журнал.
- Отчёты «за день» и «за период» переписаны так, чтобы база искала по индексу по времени, а не перебирала все записи.
- Загрузка клуба считает каждое посещение только по тем часам, когда человек был в клубе.
- Отключена JIT-компиляция запросов: на наших коротких запросах она только добавляла до 0,3 секунды.
- Длинные списки и так ограничены (клиенты — 300 строк, заявки — 200, лента проходов — 200), постраничная загрузка пока не нужна.

## Как повторить (для разработчика)

```
cd apps/api
npm run perf -- --generate     # отдельная база fitnes_perf: тестовые данные + объём сети (около 2 минут)
npm run perf                   # замер; --sql покажет самые долгие запросы, --only "когорты,загрузка" — выбранные экраны
```

Рабочую базу скрипт не трогает. Повторять замер стоит после крупных изменений в отчётах и перед переносом из 1С.
